<design_defaults status="defaults (DF-xx) the blueprint applies and the user may override">
  DF-01 Error-returning boundary. Pure validators, transitions and can() return
        a typed Decision or Result (ok, or error with a stable code). Use cases
        convert errors into a small AppError taxonomy (Unauthenticated,
        Forbidden, NotFound, Conflict, Validation) and central handlers map it to
        application/problem+json with title and detail in Spanish and a stable
        English code plus trace_id. Routers contain no business try / except.
        [SAD AD-08] [SAD AD-12] [CONV RFC 9457] [CONV defense in depth]
  DF-02 Injection. Every mutating use case obtains actor, ids and timestamps from
        the session, IdGenerator and Clock, then passes them to pure domain
        functions as arguments. [HC-09]
  DF-03 can(actor, action, resource_context) with action names like task.create
        [SAD 4.4]; policy as a declarative table role x action with optional
        predicates for the criteria in SAD 4.1 (membership, assignment,
        authorship, creator, requester). Resources are described by a small
        immutable context (project member roles, assignee_id, author_id,
        creator_id, requester_id) so the policy never imports a module. Default
        deny. Routers declare the action through one dependency; the matrix is
        exhaustively tested. The permission matrix is an ASSUMPTION until SRS 7.2
        is supplied (H-12).
  DF-04 Transition tables as readonly data plus a guard map for predicate
        transitions (fixing requires a linked open fix). Every ordered pair of
        the six states (36, self-transitions included) is explicitly allowed or
        denied and tested. DEC default carried from v2: REPORT_FIX and
        RESOLVE_FIX are dedicated transitions guarded by a linked open fix and
        bypass the manual table; the manual transition endpoint cannot enter
        fixing [SAD G-12] [SAD E-03].
  DF-05 Selectors are pure functions; repositories return the minimal rows (for
        example task counts and points by status) and the selector computes
        progress. Points owner default (H-04): user_stories, following the SAD
        module table and the velocity definition; the progress selector follows
        SAD 4.12 (completed points over total points, story completion derived
        from its tasks) and also exposes task counts; state both consequences.
  DF-06 Orchestration. A multi-module operation is one small module in
        app/orchestration, receiving repository ports and the UnitOfWork,
        returning a typed result and committing once. A single-module operation
        stays in its module. No god object. [SAD AD-07] [CONV SRP]
  DF-07 Bootstrap. create_app() builds the composition root; startup validates
        settings and opens the pool; readiness compares the Alembic revision
        with head [SAD AD-13]; no create_all, no automatic migration outside
        development, no automatic seed. Resolves H-11.
  DF-08 Collections. limit and offset with a default and a maximum from the
        environment, stable ordering (created_at, id), response envelope with
        items, total, limit, offset [SAD RNF-REN-02 Propuesto]. Resolve N+1 with
        explicit eager loading and test the query count of list endpoints.
  DF-09 Failure containment. Unhandled errors produce a generic 500 problem
        document with trace_id and a server-side log with the stack; nothing
        internal reaches the client. [SAD AD-12, RNF-FIA-04]
  DF-10 Session. A sessions row (id, user_id, created_at, expires_at at 8 h from
        SAD 4.1, revoked_at). The JWT (algorithm pinned, claims iss, aud, sub,
        sid, jti, iat, exp) carries the session id and is delivered in an
        HttpOnly, Secure cookie (Secure may be disabled only by an explicit
        development setting). Every request validates the session row and the
        user's is_active, so logout and deactivation take effect immediately
        [BKL RN-22]. State-changing requests require an X-CSRF-Token header equal
        to the CSRF cookie (double submit) [CONV OWASP CSRF]; CORS uses an exact
        origin allowlist from the environment with credentials, never a
        wildcard. SameSite is configurable and the blueprint states the
        deployment condition under which the frontend and API are same-site.
        DEC options: (a) this default, (b) Bearer JWT in the Authorization header
        per the literal BKL 9, which drops CSRF but contradicts G-03 and moves
        the token into script-readable storage on the client. Refresh tokens are
        reserved and listed as a Known Limitation. Password hashing: Argon2id
        with parameters from the environment [SAD G-02]; unknown e-mail paths run
        a dummy verification; failed-attempt counters with a lock window close
        G-07 (DEC: implement or reserve, default implement, thresholds from the
        environment); temporary credential and must_change_password follow
        E-08 (while it is set, every route except change-password and logout is
        refused).
  DF-11 Files. Python modules snake_case; domain modules named by role
        (entities.py, rules.py, transitions.py, policy.py); tests test_*.py with
        function names in Spanish ASCII; absolute imports from the app package;
        one public concept per module; files at most 300 lines.
  DF-12 Concurrency. Integer row_version on mutable aggregates (at least tasks),
        incremented by the ORM version counter; status-changing requests carry
        expected_version and a mismatch is a 409 with code STALE_VERSION.
        [Archetype Convention Addition, resolves H-18]
  DF-13 Identifiers. UUID v4 through the IdGenerator, exposed as strings; the
        seed uses deterministic ids so tests and docs are reproducible.
  DF-14 Time. timestamptz everywhere, UTC, ISO 8601 with offset in JSON [SAD 4.9
        UTC decision]; naive datetimes are rejected by Ruff DTZ; business
        timestamps never come from database defaults.
  DF-15 Deletion and cascades. Users are never hard-deleted. Projects are soft
        deleted (deleted_at) by the Administrador and every query excludes them;
        physical purge is reserved. "Archive" (HU-10) is NOT invented: list it
        as an uncovered requirement and ask. Cascade rules follow E-09 and are
        documented per foreign key. [SAD D-23 pending] [SAD E-09] [BKL HU-10]
  DF-16 Persistence of enums. VARCHAR plus CHECK constraint, not PostgreSQL ENUM
        types, so that expand-and-contract migrations stay cheap [SAD 5.5].
        Constraint names follow one naming convention declared on the metadata.
  DF-17 Quality tooling. Ruff covers lint and format (Black dropped as redundant,
        DEC because BKL 9 lists it); Ruff rule sets at least E, F, I, B, UP, S,
        DTZ, T20, N, SIM, PT, RUF and TID251 for HC-09, with justified
        per-file ignores (for example S101 in tests); mypy strict with the
        Pydantic plugin; import-linter contracts for BR-1..BR-4. Task runner:
        Makefile (DEC: the team's operating system is unknown, so document the
        Docker and WSL path; ASM).
  DF-18 Test database. Unit and application tests run on in-memory fakes with no
        database; integration, API and security tests run on real PostgreSQL
        (a compose service locally, a service container in CI) created per
        session with a temporary database and migrations applied through
        Alembic, never through create_all [CONV test against the production
        engine].
  DF-19 Audit. audit_logs is append-only: the repository exposes add and read
        only, and the API has no update or delete route [SAD RNF-SEG-07]
        [BKL RN-21]. Mandatory events are the ones the SAD declares
        (task.status_changed, user.deactivated and the Tier B ones); extra
        events such as login failures are [Archetype Convention Addition] and a
        DEC.
  DF-20 Notification reference. SAD 3.5 stores a client NavState in action_url,
        which is a frontend concept; the server stores a neutral reference
        (entity_type, entity_id, project_id) and the client builds the NavState.
        [Archetype Convention Addition, resolves H-23]
</design_defaults>

        <rule id="R2" name="Transactional Example">
          Implement the confirmed flow end to end (default F1 and its
          acceptance scenarios) so that it:
          - Starts at an HTTP request, traverses ALL four SAD layers, writes
            through repositories inside one UnitOfWork transaction on PostgreSQL,
            and returns the updated representation.
          - Uses DashNode vocabulary and Backlog-derived seed data in Spanish
            (project, epic, stories HU-xx, tasks, three or four users with
            distinct roles, tasks in different states). Never generic names.
          - Exercises: session authentication, can(), TASK_TRANSITIONS, an
            orchestration operation (domain change + notification + audit entry

          - Runs out of the box after the lock-and-install step, the migration
            command and the seed command (or with Docker Compose), without any
            modification: from an empty database to a working Swagger page.
          - Documents the demo accounts as non-secret demo data (HC-06).
        </rule>

        <rule id="R3" name="Testing and Coverage">
          Stack: pytest + pytest-cov (branch coverage) + httpx test client.
          - Every public function and method in the domain and application
            layers has at least one unit test.
          - Enforced thresholds (lines and branches) per group, excluding
            type-only modules, empty package markers and seed data:
            100 percent for domain packages, the can() policy, transition
            tables, validators and selectors; 95 percent for module application
            layers and app/orchestration; 90 percent for infrastructure;
            presentation (routers) is reported, not enforced, and covered by
            the API and security suites. The SAD floor is 70 percent line
            coverage in authorization and rules (RNF-MAN-01): the archetype is
            stricter on purpose, as a reference implementation [Archetype
            Convention Addition]. Coverage.py has no per-path threshold, so
            enforce each group with "coverage report --include=... --fail-under=N"
            invoked by the coverage task, and set source to the app package so
            that untested files count as 0 percent. A run that misses a
            threshold must fail.
          - Table-driven exhaustive tests for: can() (every role x action,
            including each authorization criterion used and the default deny),
            TASK_TRANSITIONS (all 36 ordered pairs), validators (including URL
            schemes: http and https only, javascript: and data: rejected),
            selectors, and the Pydantic request schemas (unknown fields
            rejected).
          - Application tests on in-memory fakes with FakeClock and a sequential
            fake IdGenerator: use-case results, orchestration order and the
            single commit, rollback on failure, error mapping.
          - Integration tests on real PostgreSQL: repositories, constraints
            (unique e-mail case-insensitive, CHECKs, foreign keys, version
            conflict), transaction rollback of the F1 operation, migrations up
            and down, readiness against an older revision, query count of list
            endpoints.
          - API tests through the HTTP client: cookies, CSRF, CORS preflight,
            problem+json shape, pagination envelope, Location header.
          - Security tests: every route against the public allowlist, 401 and
            403 sweep, BOLA attempts on ids of another project, mass assignment
            of role and actor fields, password_hash absent from every response,
            SQL metacharacters inert, response equality and comparable timing of
            failed logins, throttle, expired and revoked sessions.
          - Style: AAA (Arrange, Act, Assert) or GWT (Given, When, Then), names
            in Spanish ASCII. No real clock, no network, no sleeping, no shared
            state between tests.
          - Fitness tests (tests/architecture): import-linter contracts for
            BR-1..BR-4, HC-09 and HC-10; a route inspection that fails when a
